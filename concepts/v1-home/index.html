Most mockups break your screenshots.

Text gets stretched, tab bars get cropped and headers disappear under the notch. bezelkit compares your image with the device's real screen and fits it properly on 26 devices. It's one HTML tag.

npm i bezelkit

Or drag an image onto the phone. It stays in your browser and nothing is uploaded.

01 · SAME SHAPE

Matches within 4%: cover

A 1206×2622 screenshot on a 402×874 screen. The shapes agree, so it fills the screen edge to edge and loses at most a few pixels.

02 · MUCH TALLER

A full-page capture: scroll

This one is nearly three screens long. Cropping would throw most of it away, so bezelkit keeps the width and lets the screen scroll, the way the real phone would.

03 · A LITTLE TALLER

Up to 15% taller: pin to top

Headers usually matter more than footers, so the image is anchored at the top and the bottom is trimmed. If the tab bar matters, set fit="contain".

04 · WIDER

From an older phone: letterbox

A 16:9 screenshot on a 19.5:9 screen. It is centred instead of stretched, and the empty bands are painted with colours sampled from the image's own top and bottom rows.

05 · LIVE HTML

Your markup: safe areas

Slotted HTML and iframes are padded clear of the Dynamic Island and home indicator, with a status bar drawn in. For full-bleed layouts, use safe-area="none" and read --bezel-safe-top yourself.

One tag. Every device.

Change one attribute to switch between phones, tablets, laptops, desktops, watches and browser windows. Every frame uses the device's real screen size in CSS pixels, so screenshots map 1:1 and embedded sites hit their real breakpoints. Hover over the device to tilt it.

<bezel-device device="iphone-17-pro" src="shot.png">

Devices

    
Every frame is drawn in CSS at the device's real CSS-pixel viewport, so it stays sharp at any size. Click any device to open it in the playground.

    

  


  

    
API

    
A single element works in plain HTML, React 19, Vue, Svelte, Astro, MDX and Webflow embeds. It scales to the width you give it (or fits inside both width and height if you set both).

    

      
AttributeValuesWhat it does

      
        
deviceiphone-17-pro … see galleryWhich frame to render. Short aliases work too: iphone, android, ipad, macbook, watch, browser.

        
srcimage · video · URLContent type is detected from the extension. URLs are embedded as a live iframe at the device's true viewport. Leave it out to slot your own HTML.

        
fitauto cover top contain scroll fill noneauto compares the image's shape with the screen: if they match (±4%) it covers, if the image is much taller it scrolls, if it's a bit taller it pins to the top, and if it's wider it letterboxes with sampled edge colours.

        
colorname or CSS colourOfficial finish names (deep-blue, cosmic orange) or any CSS colour.

        
orientationportrait landscapePhones and tablets. Content rotates with the device, so it stays upright.

        
chromeauto on offDraws a status bar and home indicator. With auto they're on for HTML and iframes and off for screenshots, which already have their own.

        
safe-areaauto pad nonepad keeps content clear of the notch and home indicator. Slotted HTML also gets --bezel-safe-top/-bottom CSS variables.

        
themelight darkStatus bar ink and browser toolbar colours.

        
url · viewportacme.dev · 1440x900For browser frames: the address-bar text and the window size.

        
glare · shadowboolean · noneAdds a subtle screen reflection; shadow="none" turns off the drop shadow.

      
    

    
Events: bezel-fit fires with { fit, mediaRatio, screenRatio, mismatch } once media loads, so you can warn authors about screenshots from the wrong device. Styling hooks: ::part(screen), ::part(frame), --bezel-screen-bg. Custom devices: defineDevice({ id, screen: { w, h, radius }, … }).
